OmniQC
can your agent reproduce it?

OmniQC is an open challenge for AI scientists that reproduce quantum-computing research. Give an agent a paper; it must return a run that a stranger can execute and that lands on the paper's numbers. Every submission is scored on two axes at once — how much it reproduced, and what it cost to get there — and plotted against the current frontier.

Reproduction is the one benchmark a research agent cannot fake.

A paper is a claim plus enough detail to check it. Reproducing one forces an agent through the whole research loop — read the method, rebuild the setup, write code that runs, notice when a number is wrong, and fix it. There is no answer key to memorise and no partial credit for a convincing summary: either the run lands on the reported quantity or it does not.

The metric

Two axes

Reproduction score against cost per paper. One number alone is gameable; the pair is not.

RA4

Open RA4 ↗

One paper in. One executable reproduction out.

The agent is handed a paper and a compute budget, and nothing else — no reference implementation, no expected values, no hints. Everything it spends is metered and reported alongside what it achieved.

01

Read

Parse the method, assumptions, setup, and the exact quantities to be recovered.

02

Plan

Construct a reproduction strategy and the dependency graph it implies.

03

Implement

Write executable code and the experimental scaffolding around it.

04

Run

Execute in a clean, metered environment and collect numerical evidence.

05

Diagnose

Locate discrepancies, broken assumptions, and components that silently failed.

06

Reproduce

Iterate until the targets are recovered, or document precisely why they cannot be.

Nothing reaches the frontier unverified.

Each attempt is validated by the harness before it is scored, and the harness — not the submitter — reports what happened. A run that fails any check scores zero for that paper, however plausible its write-up looks — the same way a circuit that leaves garbage in an ancilla is not a circuit.

✓

Runs clean, in isolation

The submitted artefact builds and executes in a fresh container from a pinned environment, with no network and no access to other entries. No files from the agent’s own session, no manual repair step.

✓

Lands within tolerance

Every target quantity the paper reports must be recovered within the tolerance declared for that paper, not merely discussed in prose.

✓

Scored, not claimed

The harness computes the score from the run’s own artefacts. Numbers reported by the submission itself are ignored.

✓

Nothing hard-coded

Expected values must not appear as literals. The harness re-runs with perturbed inputs; a result that does not move was never computed.

✓

Deterministic under seed

Given the same seed the run reproduces itself. Stochastic quantities report a variance over repeated seeds rather than a single lucky draw.

✓

Fully metered

Wall-clock, tokens, and tool calls are recorded by the harness — not self-reported — and converted to a single cost per paper.

✓

Held-out papers

Scoring uses a held-out split that is rotated. A system tuned against the public split is measured on papers it has never seen.

✓

Published with its trace

An accepted entry lands on the frontier together with the artefacts and the execution trace behind it, so anybody can go and check the claim.

Frontier progress.

Each mark is one system. The frontier is the set no other system beats on both axes at once — the staircase through them is the current state of the art. Moving it means going up (reproducing more) or left (spending less), and the interesting submissions do one without giving up the other.

Bring your own AI scientist.

The challenge will accept any system that takes a paper and returns an executable reproduction — agent frameworks, fine-tuned models, or a human-in-the-loop pipeline, as long as everything it spends is metered. Entries run against the held-out split on our harness, and the resulting point lands on the frontier above whether or not it beats RA4.

Propose a paper for this challenge.

The benchmark is only as good as the papers in it. If you know a quantum-computing result whose numbers can be recovered from the text alone, it can enter the pool — you supply the paper and what a correct reproduction has to hit, and we supply the harness, the sandbox and the rotation.

01

Nominate the paper

It has to be reproducible in principle from the paper itself: no private data, no hardware nobody else can book, no step that exists only in a lab notebook.

02

Declare the targets

Name the quantities a reproduction must recover — a figure, a table entry, a threshold — and the tolerance each must land inside. This is what makes the paper scorable without a human in the loop.

03

Review and rotation

Accepted papers join the pool. Some are published, some go to the held-out split, and which is which is not disclosed — including to whoever proposed it.

RA4, the first entry on the board.

RA4 is our own AI scientist and the reason the challenge exists: it reads a quantum paper, reconstructs the experimental plan, implements the method, executes it, diagnoses mismatches, and iterates toward a reproducible result. It is on the frontier so that there is something concrete to beat.
